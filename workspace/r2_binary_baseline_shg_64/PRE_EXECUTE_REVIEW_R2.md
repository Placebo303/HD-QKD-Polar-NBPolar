## Blocking finding

**F4 — PI-facing budget/STOP text claims mechanisms run.py does not implement.** In run.py `MAX_PARALLEL`, `BUDGET_WALL_S_TOTAL`, `HARD_TERMINATE_MARGIN_S` are defined but never used (grep; `mp` unused). `main()` runs all blocks serially in one process: no 8-way fork, no parent hard-terminate, no total-wall check, and no `resource_abort_total_wall_budget_not_started` status. Yet AUTHORIZATION_PROMPT.md ("___ 路并行 / 超预算即 STOP"; table "8-way"), contract §6 ("8 路并行 fork"; "父进程 120 s margin 硬终止") and §7 ("总 wall 预算耗尽 ⇒ 停止启动新任务 ... not_started") describe them as real; prereg.md Budget paragraph likewise. The per-block wall check is also cumulative per block (from block start), not per grid point as worded. Concrete risk: the PI would confirm parallelism/STOP rules that do not exist, and the run auto-starts with the 4 h stop unenforced (serial worst case ~3.0 h leaves only ~1 h margin, SCL-arm cost not in the estimate). Same class as round-1 F3.
Fix (either): (a) implement a minimal total-wall check in the block loop (stop starting new blocks after BUDGET_WALL_S_TOTAL measured from run start, record the rest as resource_abort_total_wall_budget_not_started) and correct the wording to "serial single process"; or (b) amend authorization/contract §6-§7/prereg to "serial single process; no in-code total-wall STOP; operator monitors wall and kills at 4 h, recording remaining blocks as not started; 8-way/hard-terminate not implemented", with the projected serial time stated. Then a quick re-check (no scientific change).
